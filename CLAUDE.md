# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Product

**Buds** — a mobile 2D top-down RPG (Unity). Players create a "bud" (ziomek / ziomeczka with a mood and a style) on the website, link it to the game with a 6-character pairing code, then progress in the game: map, NPC quests, combat, mini-games, gathering and crafting. XP is earned only in the game. UI copy is Polish; adjectives must agree with the bud's gender (`moodLabel`, `moodBlurb`, `byGender`).

## Layout

- `apps/unity` — the game (Unity 6.6, URP 2D, Input System). Code in `Assets/Buds/Scripts/{Runtime,Editor}`, tests in `Assets/Buds/Tests/EditMode`.
- `apps/web` — Next.js 15 site (Vercel): landing (a scroll "journey": a street (pavements, centre line, zebra crossings, round turns) running down one side past a stop, across to the other side, and so on (`Trail`); the bud walks it with the scroll (scroll position maps onto a point of the street at one fixed ratio; the bud follows it closely with a ~0.1 s smoothing so a wheel notch is a few steps, steps follow the distance walked with a minimum step time, facing has hysteresis), at most six stops (the main things to do in the game); a stop opens while the bud is at or past it and folds away when it walks back, each stop opens an adventure with a game screenshot from `public/screens` and a bit of true Buds trivia from the content; player-facing only, never how the game works inside; district gallery tabs, compact tabbed creator; `Reveal`/`JourneyBits` components, styles in `app/journey.css`, transform/opacity animations only, honours reduced motion), bud profile + pairing code, ranking, account (`/konto`), privacy page.
- `apps/api` — Hono API (Render, `render.yaml` Blueprint; Railway still works with `apps/api/railway.json`): buds, guest tokens, pairing, sprite-sheet PNGs. Rate limits key on the client IP; on Render `CLIENT_IP_HEADER=cf-connecting-ip` (client-sent X-Real-IP / X-Forwarded-For can be faked there).
- `packages/shared` — the vector bud generator (`src/bud/vector.ts`, chibi SVG), level curve, zod schemas. Single source of truth for how a bud looks.
- `supabase/` — migrations (`buds`, `bud_tokens`, `bud_pair_codes`).
- `tools/` — `check-migrations.mjs`, `export-guest-sheet.ts` (regenerates the offline guest sprite in Unity), `world/` (district art and maps: `export-art.ts` renders every prop in `world/art/*` to `Resources/World/*.png` + `props.json`; `export-maps.ts` builds the five district maps (Dzika Puszcza is `world/maps/dzika-puszcza.ts`; the old plots are built by `world/maps/places.ts`), the tutorial island and the rooms (`world/maps/interiors.ts`) from `world/maps/*` into `Resources/Maps/<id>.txt` and validates them).

## Conventions

- **Bud look is generated, never stored as pixels.** The API stores `look` (jsonb) and rasterises the vector art with resvg at `GET /v1/buds/:slug/sheet.png` (columns = walk frames 0..2, rows = down, side-facing-left, up; 128×192 px cells, 160×240 SVG units, feet at y=220). The game downloads that sheet; never port the generator to C#. After changing the generator, rerun `tools/export-guest-sheet.ts` (offline guest sprite in Unity).
- Visual style follows the Buds design system (tokens: surface/paper/ink, lime `buds`, `gold` for the single call to action per screen, `rep` secondary, `alert` destructive; outlined interactive elements, hard lips/drops, no soft shadows or gradients, no emoji in UI). Web tokens live in `apps/web/app/globals.css`, Unity tokens and components in `UiKit.cs` — keep them in sync.
- Fonts: Rubik everywhere. Web self-hosts the variable font (`apps/web/app/fonts/Rubik-Variable.woff2`, Latin + Polish subset, via `next/font/local`; never `next/font/google`, which fetches at build time and breaks CI when Google Fonts is flaky); Unity uses static Rubik-Black/Rubik-Bold instances (fontTools) because legacy Text can't drive a variable font's weight axis.
- Level curve lives in `packages/shared/src/level.ts` and is mirrored in `Progression.cs` — change both together.
- XP, coins, gems and owned items must only ever be granted by the server (game reports events, API validates). Never trust the client.
- Monetisation groundwork: one item catalog in `packages/shared/src/catalog.ts` (kinds, design-system rarities, `free`/`coins`/`gems`, `premium`, `available`); ownership in `bud_items` (server-written). The API rejects looks that wear items the bud doesn't own (`lockedItems`). No pay-to-win: real money buys looks, convenience and premium rides/weapons that are exactly as strong as an earned `twin` (at most 2 levels earlier; `packages/shared/src/premium.ts`, enforced by `gearProblems`). Premium shop: `POST /v1/premium/:itemId/buy` (atomic `buy_item_gems`); gems only from verified purchases (`grant_gems`). Plan and order of work: `docs/roadmap.md`.
- NPCs and quests: content per district in `packages/shared/src/content/<district>.ts` (schema/rules in `quests.ts`, how-to in `docs/questy.md`). Quests can grant a catalog item (`rewardItem`). Skills (`packages/shared/src/skills.ts`): one point per level, spent only through `POST /v1/buds/me/skills/:id/upgrade` (atomic `upgrade_skill` SQL function); the in-game Bud panel (`BudPanel.cs`, `GameBootstrap.Panel.cs`) shows profile, inventory and skills. Item/skill icons live in `tools/world/art/icons.ts`. The API grants quest XP once via `POST /v1/buds/me/quests/:id/complete` (validated with `questBlocker`, atomic `complete_quest` SQL function). After editing content run `tools/world/export-quests.ts`; the game logic lives in `QuestLog` (plain class) and `QuestWorld`/`GameBootstrap.Quests.cs`.
- Districts: Miasto Ziomków (start, hub), Dzika Puszcza (level 2, west of the city park), Las Palmas, Dwór Carski, Los Karkos — design in `docs/districts.md`, registry in `packages/shared/src/districts.ts`, mirrored in Unity `Districts.cs` (change both together). A district is a big map (city centre + outskirts) and, later, its own multiplayer room.
- Guest auth: `Authorization: Bearer <player token>`; only sha256 hashes are stored. One bud can have many tokens (one per device).
- Every request/response shape lives in `packages/shared` as a zod schema. New API behaviour touching auth, CORS, headers or limits needs a test.
- Migrations: never edit one that is already on `main`; every new table gets RLS enabled.
- Unity: world and UI are built from code at runtime; the only scene is `Assets/Buds/Scenes/Main.unity` (camera + `GameBootstrap`). 1 tile = 1 world unit.
- Maps are text files (`Resources/Maps/<district>.txt`, format documented in `MapFormat.cs`): a character grid + legend (`ground [+ prop|variant] [!solid]`), ground styles, scatter rules, signs, exits, zones. The file is the single source of truth for collision (the multiplayer server will read it too). Edit the generator in `tools/world/maps` or the file directly; `DistrictMapTests` check every map (spawn, exits both ways, reachability, known props). Buildings: odd footprint widths, anchor = middle of the bottom row.
- Interiors: a district map's `[doors]` (building anchor → room id) lead into small room maps (`kind = interior`, `outside = <district>`, id `<district>-<place>`), built by `tools/world/maps/interiors.ts`; the room's doormat exit leads back in front of the door (`WorldMap.ArrivalFrom`). `m.door()` puts an entrance mat in front and clears 1×1 props there. Travel between maps fades (`GameBootstrap.Travel`).
- Hidden caches (skrytki): `caches` in `content/<district>.ts` (schema in `packages/shared/src/caches.ts`), invisible until the bud is within `CacheLog.RevealRadius` (Spryt widens it); coins + XP granted once by `POST /v1/buds/me/caches/:id/open` (atomic `open_cache` SQL function). Logic in `CacheLog`, view in `CacheWorld`, exported by `export-quests.ts`.
- Gear: eight slots head to toe plus the ride (`mount`) (`packages/shared/src/gear.ts`); catalog items with `slot` + `bonus` (speed / armor / luck / skill ranks, capped, gear adds at most +2 per skill). Stats formula mirrored in Unity `Quests/Gear.cs` (change both). Premium items with power must copy an earned twin (`gearProblems`, tested); drinks are never premium. Coin shop: `shop: true` items, `POST /v1/shop/:itemId/buy` (atomic `buy_item`). Luck adds cache coins on the server. Own brand names only. Details: `docs/ekwipunek.md`.
- Look: per-gender standard catalogs for hair, top, legs and shoes with their own colours (`bud/constants.ts`, append-only lists; new look fields have defaults). The look can be changed any time: Twój Bud → Profil → "Zmień wygląd" opens `CreatorScreen.ShowEdit` and saves with `PUT /v1/buds/me/look` (same look rules, only owned items; the bud is redrawn at once with a fresh sheet). The game creates buds itself: `CreatorScreen` reads `GET /v1/look/options`, previews via `GET /v1/look/sheet.png?look=<base64url>` (own rate limit), creates with `POST /v1/buds`. Details: `docs/wyglad.md`.
- New buds start on the tutorial island `wyspa-startowa` (`TUTORIAL_ISLAND` in districts.ts, `Districts.Tutorial` in Unity — not a district); its pier opens after the final quest (`wyspa-rejs`) and leads one way to Miasto Ziomków. Quest steps also have `duel` (win against an enemy). Districts are 176×132; the old `[plots]` were built on (`tools/world/maps/places.ts`: stadium, funfair, market, square, waterfall, tiki village, marina, racecourse, mill, orangery, mine, motocross, power plant), their content is `content/new-places.ts`; a plot still reserved must stay clear.
- Gear table: `packages/shared/src/gear-items.ts` (100+ items, `minLevel` gates wearing and buying, held items are weapons with a `weapon` kind; icons in `tools/world/art/gear-icons.ts`). Duels: turn-based, resolved on the server one turn at a time (`combat.ts` `playTurn`, integer maths, seeded RNG in the state; `POST /v1/fights`, `/:id/move`, `/:id/flee`; atomic `finish_fight`). Moves come from the weapon kind and carry an animation tag the game plays: `FightStage` is a 3D night street built far from the map (the main camera leaves `FollowCamera` for a film camera: dolly-in intro, push towards blows, snap zoom + slow motion on crits, orbit on a knockout; fighters are camera-facing cards that lunge, jump, dodge into depth and fall flat), `FightScreen` is the fighting-game HUD over it (plates with HP and stats, moves, result) and the comic effects pinned to the fighters and clamped on screen; it hides the world HUD while open. Learned moves (`MOVE_UPGRADES`, `learnedMoves`): every weapon move has a stronger version unlocked by level + the weapon's skill rank (training and gear count; Garda → Kontra with Przetrwanie); it replaces the old move on the same button (the row never grows), exported as `moveUpgrades` (`QuestContent.LearnedMoves`), shown in Twój Bud → Ciosy, and "Nowy cios: …" joins the level-up / skill / equip toast. Held weapons sit in the drawn near hand (`BudSheet.SideHand`, mirrored from `vector.ts`) with the hand cut from the frame drawn over the grip (`SideHandCap`). Opponents: `enemies` in `content/<district>.ts` via `scaledEnemy` (stats from level), sheets in `Resources/Enemies/`; loot by rarity tier (`rollLoot`). Balance is simulated in `packages/shared/test/combat.test.ts`. Details: `docs/pojedynki.md`.
- Training, perks, drinks, rides (`docs/umiejetnosci.md`): effective skill rank = spent points + training ranks (`effectiveRank`, every 100 training XP); ranks 3 and 5 unlock perks (`PERKS`, derived, never stored; special duel moves via `PERK_MOVES`). Training stations: `content/training.ts`, mini-game `TimingGame`/`TrainingScreen`, `POST /v1/buds/me/training/:spotId` (atomic `train` with a cooldown). Energy drinks: `kind: consumable` with `drink` (boosts in `consumables.ts`), bought repeatedly (`buy_consumable`), drunk via `POST /v1/buds/me/consumables/:id/use`; the server applies boosts in duels, caches and training. Rides: the `mount` slot with `mountSpeed` (outside the gear speed cap), drawn by `BudController.SetRide` from `jazda-<kind>-bok/-przod/-tyl`, speed in `Rides.SpeedMultiplier`; outdoors only. Never for real money (`gearProblems`).
- Accounts: Supabase Auth (e-mail + password) on the website (`/konto`); the API verifies account tokens with the project JWKS (ES256) or the legacy HS256 secret (`middleware/auth.ts`). A bud belongs to an account via `buds.user_id` (created while signed in, claimed with the guest token, or linked from the game: Twój Bud → "Połącz z kontem" shows a pairing code that `/konto` redeems via `POST /v1/account/buds/link`). The game signs in too (pairing screen → "Zaloguj się na konto", `LoginScreen`, `GameBootstrap.Login.cs`): e-mail + password straight to Supabase Auth with the public settings from `GET /v1/auth/config` (API needs `SUPABASE_URL` + `SUPABASE_PUBLISHABLE_KEY`), lists `/v1/account/buds`, and `POST /v1/account/buds/:slug/device` gives this device its own player token; the account token is never saved. The sign-in screen turns the phone upright while open (`UiKit.SetPortrait`; canvases follow the screen shape via `OrientationFit`). Signing out (Twój Bud → Profil → "Wyloguj się", tapped twice) calls `POST /v1/buds/me/logout` (forgets only this device's token), deletes the saved session and reloads the scene to the start screen; check with `-buds-logout-demo`. The website needs `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`, otherwise accounts are off. Private bud data only through `/v1/account/*`; the public profile shows name, look, level. The web reads the repo-root `.env` (next.config.ts).
- Landscape only. Phone layout (`UiKit.Mobile`, simulate on PC with `-buds-mobile`): compact plate top left with the folding quest log button beside it (Ui/zadania, red count, J), buttons top right, action button bottom left, fixed joystick bottom right (`PlayerInput.FixedStick`, multi-touch), bigger canvas on small screens (`UiKit.CanvasHeight`, canvas matches height 1280×720), closer camera (`FollowCamera.CompactTiles*`), all UI inside `SafeArea` (`GameUi.Root`). App icon: the bud in the lime cap from `Assets/Buds/buds` (generator export), applied by `BudsIcons.Configure` on every build (default icon + Android adaptive icon on a surface-900 background). Details: `docs/telefon.md`.
- Movement is `BudMotor` (plain class: four directions like a classic top-down RPG — `FourWay` keeps the current axis on a diagonal until the other wins by `AxisBias` — with acceleration, running with Shift on PC, facing hysteresis, corner assist; the phone stick never runs; walk 3.8, run 6.2 tiles/s); `BudController` only applies it. The legs are `WalkCycle` (plain class): the cycle advances with distance (one step per ~0.95 tile walking, longer when running) so feet never slide, the body rises between steps and dips on landing, starts with a step and settles feet together. NPCs: quest NPCs stand still; side characters (`wander` > 0 in content, `content/locals.ts`) stroll with `NpcWander` (plain class: inside their radius, straight up/down/left/right along clear lines only, stop and face the player within 2.4 tiles, still while anyone talks) and walk with the same `WalkCycle`. Check motion with `-buds-life-demo` (walk/run frame strips, a strolling local).
- 2.5D: the ground and physics stay on the flat XY plane; `FollowCamera` is a perspective camera tilted by `WorldView.Tilt` looking north. Everything that stands (props, characters, caches, training stations) is rotated by `WorldView.Upright` (use `WorldView.Stand` / `StandCharacter` for a standing child; physics on the parent), flat decorations stay flat. Bodies are drawn sturdy by the generator (`BULK` in `vector.ts`); characters are drawn `CharacterScale` with a ground `WorldView.Shadow`. HUD: a right-hand column of picture buttons (`UiKit.IconButton`: Twój Bud = `Resources/Ui/bud`, Mapa = treasure map `Ui/mapa` from `tools/world/art/icons.ts`, the worn ride). The map screen (`MapScreen`, M) draws `MapPicture` with the per-device fog of war (`Exploration`).
- Light: a low sun behind the camera (south-west); every standing outdoor prop lays its silhouette on the ground as a cast shadow stretched north-east (`WorldView.ShadowPoint`, batched per chunk and atlas, sort -97), characters do the same live (`CastShadow`); rooms have none (`WorldView.Sunlit`). Plants sway in rolling gusts (`SwayFor`, `Wind`); a standing bud breathes, a walking one leans into the step. Progress bars are pills (`UiKit.Bar`: outlined pill track, even gap, pill fill never thinner than its height, `PillFit` keeps the ends round at any size).
- Finish and grade (raise the whole world to the duel stage's level): every standing prop is exported through `tools/world/art/finish.ts` (warm light from the top, a cool contact shade by the ground, fine grain clipped to the silhouette); the kit draws detail for every building and tree (window recesses, reflections, curtains/blinds/lit rooms, sill flowers, door steps, awning shade, roof gravel, leaf clusters and dapples); street decals (`kratka`, `plama-oleju`, `liscie-a/-b`, `chwast`, `rysa`) are scattered by the maps. Ground layers carry a surface texture per material (`GroundLook`: grass blades, slabs with joints, asphalt grain, cobbles, boards, sand, drifting water ripples; world-space UVs, near white × `Gain`). `WorldGrade` is a global URP volume (Renderer2D has PostProcessData) with a mood per district (contrast, split toning, vignette; bloom off on phones). No curved world or horizon tricks: the user rejected them.
- Travel (`docs/podroze.md`): every road out of Miasto Ziomków crosses a wasteland map to the next city (`travel.ts` `ROUTES`, maps from `tools/world/maps/routes.ts`, mirrored in `Districts.Routes`; the road onto one needs the far city's level, `canEnterRoute`). Off the road, `ambush` opponents (`content/routes.ts`) hide in nooks the generator carves around their spots and start the duel on their own within `Ambush.SpringRadius` (EnemyView lurking/sprung, `SprungOn`). Ferrymen in every harbour (`PORTS`, `FerryScreen`) sail to another city for `ferryFare` coins via `POST /v1/buds/me/ferry` (atomic `pay_fare`). The map ahead is worked out on a worker thread (`WorldView.Prepare`/`PlanGround`, full contour cells merged into row runs), so crossing over takes a fraction of a second; check with `-buds-travel-demo` (the `[Load]` log says `ready`/`now`). Rides: "pojazd" in the UI (never "wierzchowiec"); riding steers freely in 360° (`Rides.FreeSteering`), a skateboarder stands across the board (`Rides.RiderFacing`). Graffiti walls are murals without words, one motif per wall (mandala, character, sunset, abstract wildstyle, eye, bombed tags and throw-ups; `tools/world/art/graffiti.ts`).
- Phone stick: `StickTracker` (plain class) keeps its finger only while a touch with that id is pressed this frame, so a release the game never saw (dropped frame, cancelled touch, a quick re-tap reusing the touch slot with a new id) can never lock the stick; a finger that started on the stick takes it over; `PlayerInput.ReleaseAll` on app pause/focus loss. `BudMotor.Step` drops non-finite velocities and speed multipliers; `BudController.Unwedge` steps a bud whose feet are inside a wall out to the nearest free tile after `UnwedgeSeconds` of pushing.
- Robustness: a map owns its meshes, materials and atlas and frees them in `OnDestroy` (`PropArt.Dispose`, atlases sized by `PackTextures`, never a fixed 4096²), Resources sheets are shared (`BudSheet.Shared`), downloaded sheets are freed after copying (`new BudSheet(tex, downloaded: true)`), `Resources.UnloadUnusedAssets` after every trip. Flags that lock input always reset in `finally` (`Travel`, duels); the duel screen's `Unstick` unlocks the moves when nothing has happened for `StuckSeconds`, and a broken turn animation snaps to the server state. Requests time out after 75 s until the server first answers (Render wakes up), 30 s after.
- Look: ground layers are meshes traced from blurred tile masks (`GroundShapes`, rounded corners, colour bands, no outlines) in 32×32 chunks; props are y-sorted sprites (`WorldView.SortOrderFor`) packed into one atlas per district; fences auto-join (`x-post` + `x-h`/`x-v`). Only characters carry the black outline. Sorting: ground meshes -1000…, flat decorations -100…-90, everything standing `WorldView.SortOrderFor(y)` (17000 − y·100, clamped to 0…18000, so the north end of a big map never sorts under the ground or road markings; `StandingThingsDrawOverTheGroundEverywhere`), world markers 20000. The map screen lays out names with `MapLabels` (no overlaps, tested) and shows quest targets as numbered pins that open on tap. Keep logic in plain classes so it is testable in EditMode.
- Rywalizacja (`docs/rywalizacja.md`): weekly influence over turfs (every zone, generated by `export-maps.ts` into `packages/shared/src/turfs.ts`, rooms count for their door's turf) from duels, quests, caches and training (daily cap per turf); the ruler (≥ 30, first there on a tie) collects a daily tribute; finished weeks settle once lazily (`settle_week`: titles + coins). Crews, PvP against other buds' saved fighters (Elo leagues, rematch cooldown, first 5 wins a day pay, fleeing after the first exchange is a loss) and the Bazar (loot/shop gear only, 10% fee). All writes are atomic SQL functions in `20261017000000_rivalry.sql`, mirrored by `store/memory-rivalry.ts`; routes in `apps/api/src/rivalry.ts`; game: `RivalryScreen`, `GameBootstrap.Rivalry.cs`, `Quests/Rivalry.cs`.
- Effects are comic street art, never generic (no confetti): `tools/world/art/fx.ts` → `Resources/Ui/Fx` (impact words per blow, crit focus lines + halftone, VS sticker, sprayed K.O. stencil, WYGRANA tag, TWÓJ REWIR stamp); preview with `export-art.ts --fx-preview out.png`.
- Training mini-games differ per skill (`Quests/TrainingGames.cs`, plain classes with a perfect `Bot` for tests): Spryt timing, Walka combos, Flow rhythm, Graffiti stencil (hold), Surfing balance, Przetrwanie runner; all report a 0–5 score to the same endpoint.
- Talking to the server never shows text over the UI: `NetSpinner` (a small ring, top-right corner, own canvas) turns while `BudsApi.InFlight > 0` for over 0.3 s; check with `-buds-net-demo` and an unreachable `-buds-api`.
- Gear stats must be believable for the item and visible in play: the equip toast says what changed (`Gear.Diff`), duels show "(+N ze sprzętu)", caches show the coins Szczęście added. The Flow rhythm's tempo follows the bud's Flow rank (slow and wide for beginners).
- Secrets only via env vars; `.env.example` documents every variable.

## CI (must stay green)

`CI / Lint`, `CI / Type check`, `CI / Build Web`, `CI / API security tests`, `CI / Migration drift check`, `CI / Secret scan`, `Security checks / Secrets and dependency audit`. Unity is not in CI yet (needs a Unity license secret, e.g. GameCI).

# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Product

**Buds** — a mobile 2D top-down RPG (Unity). Players create a "bud" (ziomek / ziomeczka with a mood and a style) on the website, link it to the game with a 6-character pairing code, then progress in the game: map, NPC quests, combat, mini-games, gathering and crafting. XP is earned only in the game. UI copy is Polish; adjectives must agree with the bud's gender (`moodLabel`, `moodBlurb`, `byGender`).

## Layout

- `apps/unity` — the game (Unity 6.6, URP 2D, Input System). Code in `Assets/Buds/Scripts/{Runtime,Editor}`, tests in `Assets/Buds/Tests/EditMode`.
- `apps/web` — Next.js 15 site (Vercel): landing (a scroll "journey": a street (pavements, centre line, zebra crossings, round turns) running down one side past a stop, across to the other side, and so on (`Trail`); the bud walks it with the scroll (scroll position maps onto a point of the street at one fixed ratio; the bud follows it closely with a ~0.1 s smoothing so a wheel notch is a few steps, steps follow the distance walked with a minimum step time, facing has hysteresis), at most six stops (the main things to do in the game: the island, the locals' quests, duels, travel over the wastelands, the own district, playing together and Rewiry); a stop opens while the bud is at or past it and folds away when it walks back, each stop opens an adventure with a game screenshot from `public/screens` and a bit of true Buds trivia from the content; player-facing only, never how the game works inside; the world in numbers counted from the content (`CountUp`), the growth cards (gear, rides, training), the gallery of places (every city, the wastelands, the rooms; arrow keys, swipe, it moves on by itself only while on screen), compact tabbed creator; screenshots in `public/screens` are taken from the game's demos in the phone layout (1200×521, `-buds-mobile`); `SiteHeader` (the logo glides to the top on the landing page, the link of the section on screen is marked, the bar settles once scrolled); no scroll progress bar; `Reveal`/`JourneyBits` components, styles in `app/journey.css`, transform/opacity animations only, short and soft (the `--ease-arrive`/`--ease-answer` curves), honours reduced motion; smooth anchor scrolling via CSS with `data-scroll-behavior="smooth"` on <html>), bud profile + pairing code, ranking, account (`/konto`), privacy page.
- `apps/api` — Hono API (Render, `render.yaml` Blueprint; Railway still works with `apps/api/railway.json`): buds, guest tokens, pairing, sprite-sheet PNGs, the live WebSocket (`/v1/live`). Rate limits key on the client IP; on Render `CLIENT_IP_HEADER=cf-connecting-ip` (client-sent X-Real-IP / X-Forwarded-For can be faked there).
- `packages/shared` — the vector bud generator (`src/bud/vector.ts`, chibi SVG), level curve, zod schemas. Single source of truth for how a bud looks.
- `supabase/` — migrations (`buds`, `bud_tokens`, `bud_pair_codes`, …, `bud_lands`).
- `tools/` — `check-migrations.mjs`, `export-guest-sheet.ts` (regenerates the offline guest sprite in Unity), `world/` (district art and maps: `export-art.ts` renders every prop in `world/art/*` to `Resources/World/*.png` + `props.json`; `export-maps.ts` builds the five district maps (Dzika Puszcza is `world/maps/dzika-puszcza.ts`; the old plots are built by `world/maps/places.ts`), the tutorial island and the rooms (`world/maps/interiors.ts`) from `world/maps/*` into `Resources/Maps/<id>.txt` and validates them).

## Conventions

- **Bud look is generated, never stored as pixels.** The API stores `look` (jsonb) and rasterises the vector art with resvg at `GET /v1/buds/:slug/sheet.png` (columns = walk frames 0..2, rows = down, side-facing-left, up; 128×192 px cells, 160×240 SVG units, feet at y=220). The game downloads that sheet; never port the generator to C#. After changing the generator, rerun `tools/export-guest-sheet.ts` (offline guest sprite in Unity).
- UI text is outlined by `RoundStroke` (a round stroke, never the built-in four-copy `Outline`), generated discs/rings/rounded rects are mipmapped (`UiKit.Circle`/`Ring`). Visual style follows the Buds design system (tokens: surface/paper/ink, lime `buds`, `gold` for the single call to action per screen, `rep` secondary, `alert` destructive; outlined interactive elements, hard lips/drops, no soft shadows or gradients, no emoji in UI). Web tokens live in `apps/web/app/globals.css`, Unity tokens and components in `UiKit.cs` — keep them in sync.
- Fonts: Rubik everywhere. Web self-hosts the variable font (`apps/web/app/fonts/Rubik-Variable.woff2`, Latin + Polish subset, via `next/font/local`; never `next/font/google`, which fetches at build time and breaks CI when Google Fonts is flaky); Unity uses static Rubik-Black/Rubik-Bold instances (fontTools) because legacy Text can't drive a variable font's weight axis.
- Level curve lives in `packages/shared/src/level.ts` and is mirrored in `Progression.cs` — change both together.
- XP, coins, gems and owned items must only ever be granted by the server (game reports events, API validates). Never trust the client.
- Monetisation groundwork: one item catalog in `packages/shared/src/catalog.ts` (kinds, design-system rarities, `free`/`coins`/`gems`, `premium`, `available`); ownership in `bud_items` (server-written). The API rejects looks that wear items the bud doesn't own (`lockedItems`). No pay-to-win: real money buys looks, convenience and premium rides/weapons that are exactly as strong as an earned `twin` (at most 2 levels earlier; `packages/shared/src/premium.ts`, enforced by `gearProblems`). Premium shop: `POST /v1/premium/:itemId/buy` (atomic `buy_item_gems`); gems only from verified purchases (`grant_gems`). Plan and order of work: `docs/roadmap.md`.
- NPCs and quests: content per district in `packages/shared/src/content/<district>.ts` (schema/rules in `quests.ts`, how-to in `docs/questy.md`). Quests can grant a catalog item (`rewardItem`). Skills (`packages/shared/src/skills.ts`): one point per level, spent only through `POST /v1/buds/me/skills/:id/upgrade` (atomic `upgrade_skill` SQL function); the in-game Bud panel (`BudPanel.cs`, `GameBootstrap.Panel.cs`) shows profile, inventory and skills. Item/skill icons live in `tools/world/art/icons.ts`. The API grants quest XP once via `POST /v1/buds/me/quests/:id/complete` (validated with `questBlocker`, atomic `complete_quest` SQL function). After editing content run `tools/world/export-quests.ts`; the game logic lives in `QuestLog` (plain class) and `QuestWorld`/`GameBootstrap.Quests.cs`.
- Districts: Miasto Ziomków (start, hub), Dzika Puszcza (level 2, west of the city park), Las Palmas, Dwór Carski, Los Karkos — design in `docs/districts.md`, registry in `packages/shared/src/districts.ts`, mirrored in Unity `Districts.cs` (change both together). A district is a big map (city centre + outskirts) and, later, its own multiplayer room.
- Guest auth: `Authorization: Bearer <player token>`; only sha256 hashes are stored. One bud can have many tokens (one per device).
- Every request/response shape lives in `packages/shared` as a zod schema. New API behaviour touching auth, CORS, headers or limits needs a test.
- Migrations: never edit one that is already on `main`; every new table gets RLS enabled.
- Unity: world and UI are built from code at runtime; the only scene is `Assets/Buds/Scenes/Main.unity` (camera + `GameBootstrap`). 1 tile = 1 world unit.
- Maps are text files (`Resources/Maps/<district>.txt`, format documented in `MapFormat.cs`): a character grid + legend (`ground [+ prop|variant] [!solid]`), ground styles, scatter rules, signs, exits, zones. The file is the single source of truth for collision (the multiplayer server will read it too). Edit the generator in `tools/world/maps` or the file directly; `DistrictMapTests` check every map (spawn, exits both ways, reachability, known props). Buildings: odd footprint widths, anchor = middle of the bottom row.
- Interiors: a district map's `[doors]` (building anchor → room id) lead into small room maps (`kind = interior`, `outside = <district>`, id `<district>-<place>`), built by `tools/world/maps/interiors.ts`; the room's doormat exit leads back in front of the door (`WorldMap.ArrivalFrom`). `m.door()` puts an entrance mat in front and clears 1×1 props there. Travel between maps fades (`GameBootstrap.Travel`).
- Hidden caches (skrytki): `caches` in `content/<district>.ts` (schema in `packages/shared/src/caches.ts`), invisible until the bud is within `CacheLog.RevealRadius` (Spryt widens it); coins + XP granted once by `POST /v1/buds/me/caches/:id/open` (atomic `open_cache` SQL function). Logic in `CacheLog`, view in `CacheWorld`, exported by `export-quests.ts`.
- Gear: eight slots head to toe plus the ride (`mount`) (`packages/shared/src/gear.ts`); catalog items with `slot` + `bonus` (speed / armor / luck / skill ranks, capped, gear adds at most +2 per skill). Stats formula mirrored in Unity `Quests/Gear.cs` (change both). Premium items with power must copy an earned twin (`gearProblems`, tested); drinks are never premium. Coin shop: `shop: true` items, `POST /v1/shop/:itemId/buy` (atomic `buy_item`). Luck adds cache coins on the server. Own brand names only. Details: `docs/ekwipunek.md`.
- Look: per-gender standard catalogs for hair, top, legs and shoes with their own colours (`bud/constants.ts`, append-only lists; new look fields have defaults). The look can be changed any time: Twój Bud → Profil → "Zmień wygląd" opens `CreatorScreen.ShowEdit` and saves with `PUT /v1/buds/me/look` (same look rules, only owned items; the bud is redrawn at once with a fresh sheet). The game creates buds itself: `CreatorScreen` reads `GET /v1/look/options`, previews via `GET /v1/look/sheet.png?look=<base64url>` (own rate limit), creates with `POST /v1/buds`. Details: `docs/wyglad.md`.
- New buds start on the tutorial island `wyspa-startowa` (`TUTORIAL_ISLAND` in districts.ts, `Districts.Tutorial` in Unity — not a district); its pier opens after the final quest (`wyspa-rejs`) and leads one way to Miasto Ziomków. Quest steps also have `duel` (win against an enemy). Districts are 176×132; the old `[plots]` were built on (`tools/world/maps/places.ts`: stadium, funfair, market, square, waterfall, tiki village, marina, racecourse, mill, orangery, mine, motocross, power plant), their content is `content/new-places.ts`; a plot still reserved must stay clear.
- Gear table: `packages/shared/src/gear-items.ts` (100+ items, `minLevel` gates wearing and buying, held items are weapons with a `weapon` kind; icons in `tools/world/art/gear-icons.ts`). Fights (`docs/walka.md`): real time in the main view, like a mobile MOBA, no arena and no turns. Every live room runs one `Brawl` (`packages/shared/src/brawl.ts`, 20 ticks/s, plain and seeded): five buttons per bud (`kitOf`: the weapon's basic attack, two abilities, the guard, an ultimate from `ULT_LEVEL` 5, a perk's special move replacing it), every bud builds its own five per weapon (`loadout.ts`: `movePool`, `unlockOf`, `kitProblem`/`resolveKit`, saved by `PUT /v1/buds/me/moves/loadout` into `bud_loadouts`; three upgrades per move for coins from a level, `POST /v1/buds/me/moves/:id/upgrade`, atomic `upgrade_move`, `rankDamage`/`rankCooldown`/`rankHold`; Twój Bud → Ciosy), every `combat.ts` move has a shape in `ABILITIES` (melee, arc, proj, line, circle, self, dash, buff, shield: reach, wind-up, cooldown, stun/root/slow/knockback/shield/blind/weaken) and its icon (`tools/world/art/ability-icons.ts` → `Resources/Abilities`); damage is the old `damage` formula (gear, skills, perks, drinks count), health × `BRAWL_HP` (opponents × `MOB_HP`, hitting `MOB_DAMAGE`%, buds on buds `PVP_DAMAGE`%), balance simulated in `packages/shared/test/brawl.test.ts` (an even fight 15–20 s, an even PvP duel 6–25 s). Opponents of the districts stand at their spots and fight back once hit (A* `findPath`, `LEASH`, telegraphed slow blows), lurkers spring on their own (`SPRING_RADIUS`). Buds fight buds from `PVP_MIN_LEVEL` 6 anywhere but the safe zones (`SAFE_TURFS`, harbours, rooms, the tutorial island; `safeAt`); a crew (team = crew tag) never hurts itself. A knockout: down `KO_MS`, up at the nearest safe zone (`respawnPoint`) with `SPAWN_GUARD_MS` of peace, a few pocket coins lost (atomic `knockout_coins`: burned to an opponent, taken by a bud once per pair per `KO_PAIR_MS`). Rewards only through `apps/api/src/fights.ts` (`winMob` records a won fight with XP, loot and influence; `loseMob`, `street`, `shadowFight`/`exchanged`/`finishShadow`); Rewiry PvP and raids start over REST as before, then the game `summon`s the rival's saved fighter as a shadow on the street that fights only its challenger (leaving after the first blow is a loss). The turn routes are gone. Game: `GameBootstrap.Combat.cs` (glue, auto-aim, walking into reach, PC mouse aim + LMB/1–4), `Combat/BrawlRules.cs` (plain: `BrawlSelf`, `BrawlAim`, `BrawlLook`), `Combat/CombatFx.cs` (aim and red warnings on the ground; every kind of blow its own look, `StyleOf`: jabs, kicks with dust, wooden bat arcs, turning spins, stones, a sniper's tracer, paint, sound waves, shock rings, board trails, ultimates; stars and comic words, dash ghosts, K.O.), `UI/CombatPad.cs` (raised buttons in an even arc round the lime basic attack, `Layout`; hidden out of a fight, the basic attack alone with a foe within `ReadyRange`, the whole arc unfolding once blows fly; tap = nearest foe, drag = aim, "Anuluj"; gold pips = upgrades), `UI/CombatUi.cs` (health plates that never overlap, numbers, NOKAUT), `Characters/CombatPose.cs` (lunge, flinch, fall on the side, stun stars, shield ring); `EnemyView` is moved by the server; check with `-buds-fight-demo` (`FightIt` plays with the buttons). Learned moves (`MOVE_UPGRADES`, `learnedMoves`): every weapon move has a stronger version unlocked by level + the weapon's skill rank (training and gear count; Garda → Kontra with Przetrwanie); it replaces the old move on the same button, exported as `moveUpgrades` (`QuestContent.LearnedMoves`), shown in Twój Bud → Ciosy, and "Nowy cios: …" joins the level-up / skill / equip toast. Held weapons sit in the drawn near hand (`BudSheet.SideHand`, mirrored from `vector.ts`) with the hand cut from the frame drawn over the grip (`SideHandCap`). Opponents: `enemies` in `content/<district>.ts` via `scaledEnemy` (stats from level), sheets in `Resources/Enemies/`; loot by rarity tier (`rollLoot`). Details: `docs/walka.md`.
- Training, perks, drinks, rides (`docs/umiejetnosci.md`): effective skill rank = spent points + training ranks (`effectiveRank`, every 100 training XP); ranks 3 and 5 unlock perks (`PERKS`, derived, never stored; special duel moves via `PERK_MOVES`). Training stations: `content/training.ts`, mini-games `TrainingGames`/`TrainingScreen`, `POST /v1/buds/me/training/:spotId` (atomic `train` with a cooldown). Energy drinks: `kind: consumable` with `drink` (boosts in `consumables.ts`), bought repeatedly (`buy_consumable`), drunk via `POST /v1/buds/me/consumables/:id/use`; the server applies boosts in duels, caches and training. Rides: the `mount` slot with `mountSpeed` (outside the gear speed cap), drawn by `BudController.SetRide` from `jazda-<kind>-bok/-przod/-tyl`, speed in `Rides.SpeedMultiplier`; outdoors only. Never for real money (`gearProblems`).
- Account, bud and data (`docs/konto.md`): rename once in `RENAME_DAYS` (`PUT /v1/buds/me/name`, `/v1/account/buds/:slug/name`, `buds.name_changed_at`), sign out every other device (`/v1/buds/me/logout-all`, `/v1/account/buds/:slug/logout-all`), export everything as JSON (`/v1/buds/me/export`, `/v1/account/export`), delete a bud with its name typed (`DELETE /v1/buds/me`, `/v1/account/buds/:slug`: `leave_crew` first, then cascade) and the account with `USUŃ KONTO` typed (`DELETE /v1/account`: every bud, then the sign-in via the Supabase admin API); the live room drops a deleted or signed-out bud and shows a new name (`app.hooks` → `live.dropBud`/`refreshBud`, wired in index.ts). Game: Twój Bud → Profil → Konto (`AccountScreen`) and Ustawienia (`SettingsScreen`, `GameSettings` on the device: 30/60 fps, lighter graphics without the grade and WorldLife, vibration via `Haptics`, damage numbers); website: `/konto` (`AccountManage.tsx`), public `/prywatnosc`, `/regulamin`, `/usun-konto` (the store's account-deletion link). Every public name (bud, crew name and tag, district) passes `publicNameOk` (the chat filter as typed and glued). The website sends a CSP (own scripts only, connect to the API and auth only; zod is jitless in the browser, `browser.ts`), HSTS and COOP. Store build: `BudsBuild.AndroidRelease` (AAB, IL2CPP ARM64, signing only from `BUDS_KEYSTORE*` env vars; `docs/telefon.md`).
- Accounts: Supabase Auth (e-mail + password) on the website (`/konto`); accounts are created by the API (`POST /v1/auth/signup`, `signUpRequestSchema`, admin API with `email_confirm: true`, `SIGNUP_LIMIT_PER_HOUR` per IP) and signed into right after, on the website and in the game (`LoginScreen` "Nie masz konta? Załóż je", `AccountForm`), never through Supabase's `signUp` (its built-in mailer only reaches the project team, so confirmation e-mails never arrive; password reset still needs custom SMTP in the Supabase dashboard); the API verifies account tokens with the project JWKS (ES256) or the legacy HS256 secret (`middleware/auth.ts`). A bud belongs to an account via `buds.user_id` (created while signed in, claimed with the guest token, or linked from the game: Twój Bud → "Połącz z kontem" shows a pairing code that `/konto` redeems via `POST /v1/account/buds/link`). The game signs in too (pairing screen → "Zaloguj się na konto", `LoginScreen`, `GameBootstrap.Login.cs`): e-mail + password straight to Supabase Auth with the public settings from `GET /v1/auth/config` (API needs `SUPABASE_URL` + `SUPABASE_PUBLISHABLE_KEY`), lists `/v1/account/buds`, and `POST /v1/account/buds/:slug/device` gives this device its own player token; the account token is never saved. The sign-in screen turns the phone upright while open (`UiKit.SetPortrait`; canvases follow the screen shape via `OrientationFit`). Signing out (Twój Bud → Profil → "Wyloguj się", tapped twice) calls `POST /v1/buds/me/logout` (forgets only this device's token), deletes the saved session and reloads the scene to the start screen; check with `-buds-logout-demo`. The website needs `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`, otherwise accounts are off. Private bud data only through `/v1/account/*`; the public profile shows name, look, level. The web reads the repo-root `.env` (next.config.ts).
- Landscape only. Phone layout (`UiKit.Mobile`, simulate on PC with `-buds-mobile`): compact plate top left with the folding quest log button beside it (Ui/zadania, red count, J) and the chat button, a row of buttons top right, action pill bottom centre, fixed joystick bottom left (`PlayerInput.FixedStick`, multi-touch) and the fight's buttons bottom right (`CombatPad`), bigger canvas on small screens (`UiKit.CanvasHeight`, canvas matches height 1280×720), closer camera (`FollowCamera.CompactTiles*`), all UI inside `SafeArea` (`GameUi.Root`). App icon: the bud in the lime cap from `Assets/Buds/buds` (generator export), applied by `BudsIcons.Configure` on every build (default icon + Android adaptive icon on a surface-900 background). Details: `docs/telefon.md`.
- Movement is `BudMotor` (plain class: four directions like a classic top-down RPG — `FourWay` keeps the current axis on a diagonal until the other wins by `AxisBias` — with acceleration, running with Shift on PC, facing hysteresis, corner assist; the phone stick never runs; walk 3.8, run 6.2 tiles/s); `BudController` only applies it. The legs are `WalkCycle` (plain class): the cycle advances with distance (one step per ~0.95 tile walking, longer when running) so feet never slide, the body rises between steps and dips on landing, starts with a step and settles feet together. NPCs: quest NPCs stand still; side characters (`wander` > 0 in content, `content/locals.ts`) stroll with `NpcWander` (plain class: inside their radius, straight up/down/left/right along clear lines only, stop and face the player within 2.4 tiles, still while anyone talks) and walk with the same `WalkCycle`. Check motion with `-buds-life-demo` (walk/run frame strips, a strolling local).
- 2.5D: the ground and physics stay on the flat XY plane; `FollowCamera` is a perspective camera tilted by `WorldView.Tilt` looking north. Everything that stands (props, characters, caches, training stations) is rotated by `WorldView.Upright` (use `WorldView.Stand` / `StandCharacter` for a standing child; physics on the parent), flat decorations stay flat. Bodies are drawn sturdy by the generator (`BULK` in `vector.ts`); characters are drawn `CharacterScale` with a ground `WorldView.Shadow`. HUD (kept small, the world gets the screen): top left the compact player plate with the quest log and chat buttons beside it; top right one low row of 60-unit picture buttons with small captions (`UiKit.IconButton`, `GameUi.TopRow`: Twój Bud = `Resources/Ui/bud`, Mapa = treasure map `Ui/mapa` from `tools/world/art/icons.ts`, Rewiry, the worn ride); toasts sit between the two groups or under them. The map screen (`MapScreen`, M) draws `MapPicture` with the per-device fog of war (`Exploration`).
- Light: a low sun behind the camera (south-west); every standing outdoor prop lays its silhouette on the ground as a cast shadow stretched north-east (`WorldView.ShadowPoint`, batched per chunk and atlas, sort -97), characters do the same live (`CastShadow`); rooms have none (`WorldView.Sunlit`). Plants sway in rolling gusts (`SwayFor`, `Wind`); a standing bud breathes, a walking one leans into the step. Progress bars are pills (`UiKit.Bar`: outlined pill track, even gap, pill fill never thinner than its height, `PillFit` keeps the ends round at any size).
- Finish and grade (one finish for the whole world): every standing prop is exported through `tools/world/art/finish.ts` (warm light from the top, a cool contact shade by the ground, fine grain clipped to the silhouette); the kit draws detail for every building and tree (window recesses, reflections, curtains/blinds/lit rooms, sill flowers, door steps, awning shade, roof gravel, leaf clusters and dapples); street decals (`kratka`, `plama-oleju`, `liscie-a/-b`, `chwast`, `rysa`) are scattered by the maps. Ground layers carry a surface texture per material (`GroundLook`: grass blades, slabs with joints, asphalt grain, cobbles, boards, sand, drifting water ripples; world-space UVs, near white × `Gain`). `WorldGrade` is a global URP volume (Renderer2D has PostProcessData) with a mood per district (contrast, split toning, vignette; bloom off on phones). No curved world or horizon tricks: the user rejected them. Every district has its own look on top of its art (`World/DistrictLook`: water calm or lively, clear or murky; ground patchiness and how muted it is; leaves, butterflies, cloud shade, dust (no birds: the user took them out); its own things on open ground (`Extra`: mushrooms and ferns in the forest, shells and crabs on the beach, roses on the manor lawns, rubble on the scrapland); its own ground materials (`GroundLook.For(style, kinds, district)`: mown stripes on the manor lawns, wind ripples on the Las Palmas sand, cracked concrete and asphalt in Los Karkos, rock slabs and rubble everywhere they are); a wasteland takes the look of the city its road leads to, a room its district's): the ground and the water are drawn by `Resources/Shaders/BudsGround` (soft world patches `_BudsMacro`, held less saturated than what stands on it) and `BudsWater` (a drifting web of light, glints), falling back to the sprite material on a device without them; `WorldView` lays tufts along grass edges (`EdgeGrowth`), small ground details by material (`Dressing`, art `tools/world/art/dressing.ts`) and a soft contact shade under everything standing; `ArtRulesTests` keep every picture to the rules (it exists, odd footprints, standing things meet the ground near their bottom, sizes, everything the districts and life lay out has its art); `World/WorldLife` is the small life around the bud (pooled sprites from `tools/world/art/life.ts`, never touches the rules). The look stays a fixed day: no day/night and no weather (the user's choice).
- Travel (`docs/podroze.md`): every road out of Miasto Ziomków crosses a wasteland map to the next city (`travel.ts` `ROUTES`, maps from `tools/world/maps/routes.ts`, mirrored in `Districts.Routes`; the road onto one needs the far city's level, `canEnterRoute`). A city and its wastelands are seamless (`World/Seams`, `GameBootstrap.Seam.cs`): nearing a road out, the wasteland is worked out on a worker thread (`WorldView.Prepare`/`PlanGround`) and laid down behind the city's edge a few milliseconds a frame (`WorldView.CreateSpread`, at `Seams.OffsetOf`), the two outlines open on the road (`OpenEdge`), the bases split at the edge (`Seams.BaseRect`/`NeighbourBaseRect`); when the feet cross, everything shifts so the new map sits at the origin (`CrossSeam`: `BudController.Shift`, `FollowCamera.Shift`, `WorldView.Resort`, map coordinates stay what the server and the quests expect), the new map's people come in, the grade drifts over (`WorldGrade.Apply(…, seconds)`), and the old map stays as scenery until `SeamDropReach`. The wasteland's ends take on the city's ground (`routes.ts` `meetCity`). A district is switched off (not destroyed) while the bud is in one of its rooms (`parkedWorld`), so stepping back out takes milliseconds. Check with `-buds-travel-demo` (`[Seam]` log: laid, crossed, longest frame). - Phone stick: `StickTracker` (plain class) keeps its finger only while a touch with that id is pressed this frame, so a release the game never saw (dropped frame, cancelled touch, a quick re-tap reusing the touch slot with a new id) can never lock the stick; a finger that started on the stick takes it over; `PlayerInput.ReleaseAll` on app pause/focus loss. `BudMotor.Step` drops non-finite velocities and speed multipliers; `BudController.Unwedge` steps a bud whose feet are inside a wall out to the nearest free tile after `UnwedgeSeconds` of pushing.

Flags that lock input always reset in `finally` (`Travel`); a fight never stops the world, its holds (knocked out, stunned, flung by `BudController.ForceMove`) end with the server's word. Requests time out after 75 s until the server first answers (Render wakes up), 30 s after.

Only characters carry the black outline.
